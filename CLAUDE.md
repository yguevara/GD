# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

ArchiGenio (formerly SerPerf / "SGD"): a Delphi VCL desktop application for document/archive management (series documentales, expedientes, transferencias, préstamos, depósitos, etc.). UI text, identifiers and comments are in Spanish. There is no linter; the only automated tests are the DUnitX console tests in `Pruebas/` (pure-logic units only, see below).

## Projects and build

- **`ArchiGenioPro.dpr` / `.dproj` is the only project** (main form `TMAIN` in `UMAINFORM.pas`). The old `SerPerf.dpr` predecessor, its exclusive units and the side projects (`UConfig/`, `VARIABLES VIRTUALES…`, `v2Claude/`) were removed on 2026-10-30; a pre-removal copy of the sources is in `bakup/` and the history is in git. `Pruebas/` holds the DUnitX test project (`scripts/compilar.ps1 Pruebas/PruebasArchiGenio.dproj`).
- Build from the command line (Win32, Debug is the default config; output goes to `Win32\Debug\`):
  ```
  call "C:\Program Files (x86)\Embarcadero\Studio\<ver>\bin\rsvars.bat"
  msbuild ArchiGenioPro.dproj /t:Build /p:Config=Debug /p:Platform=Win32
  ```
  The project is Delphi 10.3 (Studio `20.0`; `scripts/compilar.ps1` hardcodes that `rsvars.bat`). Studio 22.0 is also installed but is not what the scripts use. The delphi-dev `delphi-build` skill and the `mcp__delphi__compile_project` tool also cover this.
- **Tests**: `scripts/compilar.ps1 Pruebas/PruebasArchiGenio.dproj`, then run `Pruebas\Win32\Debug\PruebasArchiGenio.exe` (exit code != 0 on failure; writes `resultados_pruebas.xml`). New test units must be added to `Pruebas/PruebasArchiGenio.dpr`; they can only cover units free of VCL/`UDM` (it is a console app).
- Heavy third-party dependencies must be installed in the IDE to compile: DevExpress (dx*/cx* `RS26`), FastReport (`frx*26`), TMS, JVCL/JCL, Indy, Vcl.Styles (`Light` is set in the `.dpr`, with `Windows10` as fallback; Metropolis was removed on 2026-11-12).
- Every unit is listed in the `.dpr` uses clause (`UFoo in 'UFoo.pas' {frmFoo}`); **new forms/units must be added there** (the IDE does it automatically, hand edits must too). Units in `Clasificadores/` are no longer in git's tree; the active `UCL*.pas` classifier units live in the repo root.
- `__history/`, `__recovery/`, `*.dcu`, `*.~pas` and `Win32/` are IDE/build artifacts; ignore them. Note that `Win32/Debug/*.dcu` and `ArchiGenioPro.identcache` are tracked in git, so every build dirties `git status`; don't stage them.

## Architecture

- **Startup (`ArchiGenioPro.dpr`)**: sets locale (decimal `.`, thousands `,`, date `dd/mm/yyyy`), shows `TfrmSplash`, then looks for `config.ini` next to the exe. If missing (or its edition flag mismatches `VERSION`), `Configurasys(True)` (in `USysConfig.pas`) runs the first-run configuration dialog, which writes `config.ini`. Then creates `UDM` (data module) and `MAIN`. `VERSION` is `'PROFESIONAL'` or `'BÁSICA'` and gates features.
- **`config.ini` format** (line-based, read positionally in `UCapaDatos.pas`): line 0 = DB type (`S` = SQL Server, otherwise MS Access), line 1 = server name (SQL Server) or `.mdb` path (Access), line 2 = database name (SQL Server only).
- **Data layer (`UCapaDatos.pas`, ~5.5k lines, data module `UDM`)**: single global `TFDConnection` (`UDM.Conn`) via FireDAC, with driver `MSSQL` or `MSAcc` chosen at runtime from `config.ini`. The `.dfm` holds a large number of datasets/queries bound to `Conn`; forms reference `UDM.*` directly. The module also contains FTP (Indy) handling, reserved-word lists for both SQL dialects (`SQLServerReservadas`, `AccessReservadas`), and `UpDateDB`, which runs schema migrations on connect. All SQL must work on both Access and SQL Server. `DBTableModifier.pas` (`TDBTableModifier`) is the helper for altering tables/keys across both engines. `.sql` scripts for SQL Server are in `SCRIPTS/`.
- **Main shell (`UMAINFORM.pas`, ~10k lines)**: the `TMAIN` form with menus and the docking/tree UI; it launches nearly every other form. Large cross-cutting globals (`vers`, `programver`, `VersionProgram`, `buildprogram`, `CAPP`, paths like `PathSys`) are declared in the data module's interface.
- **Security**: `USecurityClasss.pas` (`TSecurityClass`) and `md5.pas`; login in `UAutentica` + `UAutenticacion`, user admin in `UUserGest`/`UNewUser`/`UChangePass`/`UUserProperties`. Audit logs are viewed through `UAdminLog`.
- **Feature forms by prefix**: `UCL*` = classifier/catalog CRUD forms (cargo, depósitos, tipo de documento, FTP server, etc.); `UManagement*`/`UMangement*` = management forms (nodes, series, index, transfers, PDF files); `UGestEstruct`/`UNode*`/`UNewNode*` = archive structure tree; `UVeditor`/`UREditor`/`UVisorTif` = document/TIFF/rich-text viewers and editors; `UTransferencias`, `UPrestamos`, `UDepuracion` = archive workflow processes; `UExportImport*` and `UExcelExport` = import/export. Reports are FastReport (`.fr3` under `ReportesYoyo/` and `MAISEL REPORT/Report`).
- **Testable "pure" layer (newer code)**: `UAlcance` (roles `TRolNodo` + action rules over the node tree, no DB), `UAlcanceDatos` (loads a user's scope and builds a parametrized SQL filter valid on both engines; single point of scope security for the tree and document search), `UEsquemaAlcance` (idempotent schema DDL; documentary copy in `SCRIPTS/alcance_tablas.sql`), `UTopografia` (physical-location validation for a subserie/node), `UAsignacionDatos`, `UAutenticacion` (login: field validation, MD5, credential check against the DB, last user; the `UAutentica` window only captures data and `TMAIN.AplicarSesion`/`CerrarSesion` are the only place the session changes; see `docs/superpowers/specs/2026-11-12-autenticacion.md`). These deliberately avoid VCL and `TUDM` (RTL + FireDAC at most) so `Pruebas/` can compile them. Keep new business rules there rather than in forms.
- Design specs and plans for the redesign (alcance/roles, EGD assignment, topografía) are in `docs/superpowers/specs/` and `docs/superpowers/plans/`; read the relevant one before changing those areas.
- `uiapp.pas` enforces a single running instance (mutex + window message to activate the existing one).

## Conventions and gotchas

- **Encoding**: source files are ANSI/Windows-1252 (accents like `Versión`, `BÁSICA`). Preserve the file's existing encoding and BOM when editing; the delphi-dev `delphi-encoding` skill applies. Don't rewrite whole files through tools that normalize to UTF-8. Files use CRLF. The newer pure-logic units (`UAlcance`, `UAsignacionDatos`, …) are written in plain ASCII (no accents in comments/strings), which sidesteps the issue; follow that for new code. `CLAUDE.md` itself is UTF-8 and currently untracked in git.
- **Messages**: all user-facing message boxes (what used to be `MessageBox`, `MessageDlg`, `ShowMessage`) go through `UMensajes.pas` (`TMensajes.Informacion/Advertencia/Error/Exito/Confirmar`). New code must not call those RTL/VCL routines directly. `UDM.sms` calls in code being touched are migrated to `TMensajes`; untouched legacy code is converted gradually.
- **New classifiers (in progress)**: the classifier screens are being redesigned (design `docs/superpowers/specs/2026-11-12-clasificadores-design.md`). Pattern: `UClasificadorBase` (code-only form: header, un-bound `cxGrid` without Excel look, side panel with Guardar/Cancelar/Eliminar; descendants implement `AlNuevo/AlElegirFila/AlGuardar/AlEliminar`), `UClasificadorEstado` (ficha state / unsaved changes), data and rules in non-VCL units with tests (`UServidoresDatos`). Done: `UCLServidoresForm` (Servidores FTP/S3, `TMAIN.L1Click`) and `UCLArchivosForm` (Archivos, `TMAIN.A1Click`; data in `UArchivosDatos`, images in `UImagenes`; saves only what changed, the description is RTF and is kept as such). New classifier screens open EMBEDDED in the main window, not as modal windows: `TMAIN.AbrirClasificador(Form, Title, LogName, OnExit)` asks the shell for the work area (`TShellPrincipal.AbrirExterno/CerrarExterno`, which hides the tree and puts "Clasificadores > Title" in its header) and the form calls `Embeber(Host)`; changing section or closing the app goes through `TMAIN.CerrarClasificador` (asks about unsaved changes). Without the shell (`shell_clasico.flag`) the old screen is used. A `clasificadores_clasico.flag` next to the exe opens the old screens; if a new one fails to open, `UClasificadoresInterruptor.RegistrarErrorClasificador` writes `clasificadores_error.log` and the old one opens. Also done: `UCLSeriesForm` (Series y subseries, `TMAIN.S1Click`, falls back to `AbrirSeriesClasico`): series index on the left (`TFormClasificadorBase.Indice`), subseries grid, side panel with the subserie data, and a full-area editor (`MostrarVista`/`VolverALista`) for the form variables (`UVariablesEditor`: draggable list, properties, live preview; rules in `UVariablesSesion`; data in `UVariablesDatos`, series data in `USeriesDatos`; plan `docs/superpowers/plans/2026-11-12-series-subseries.md`, checklist `...-verificacion-series.md`). Variable rule: a subserie WITHOUT its `md_*` data table is freely editable; WITH it (documents exist) variables can only be ADDED (`ALTER TABLE ADD COLUMN`) and existing ones change only label/description/required/order. `TErrorCampo` now lives in `UErroresCampo`, the reserved-word lists in `UPalabrasReservadas`. Access DDL for new columns is untested (no `.mdb`). `UClasificadorBase` cannot be compiled in the console test project (AlphaControls units), so its screens are checked with window captures. Old screens (`UCLFtpServer`, ...) are kept.
- **Node home screen**: when no node is chosen, or the chosen node has no subseries, the work area shows a home (`UInicioNodo.TPanelInicio`, inside the shell's `FInicio`): counters (series, subseries, documents, without location, on loan), actions, the document life-cycle strip and a collapsible "Primeros pasos". Data in `UInicioDatos.CargarResumenInicio` (scope-filtered with `FiltroDocumentos`; nodes = selected tree node + descendants, collected in `TMAIN.ShellInicioDatos`). The shell asks via `OnInicioDatos` / `OnNodoVacio`; button/stage permissions reuse `SeccionDisponible`. No counter for transfers/purging and no recent activity on purpose (no reliable data).
- **Startup profiling**: `UTiempos.pas` (`TiemposMarca('texto')`) writes elapsed milliseconds to `tiempos_arranque.log` next to the exe, only if `perfil_arranque.flag` exists there (or `ARCHIGENIO_PERFIL=1`); otherwise it costs nothing. Marks exist in `ArchiGenioPro.dpr`, `TUDM.DataModuleCreate` and `TMAIN.FormCreate/FormShow`. The splash stays visible until `TMAIN.FormShow` ends (`SplashEstado`/`SplashCerrar` in `USplash`). Startup rules learned: no `FetchAll` on unbounded tables (`tb_log`), no per-row queries (N+1), build heavy panels with `Visible := False` before assigning `Parent` (then show), no WMI components `Active = True` in the splash. Beware: hiding `FPanelLateral` while building it changed the order of its header/tabs, so it is built visible.
- `.dfm` files are edited both by hand and by the IDE; keep property order and `object`/`end` structure intact. Editing a `.dfm` form means the matching `.pas` published field declarations must stay in sync.
- The working tree has a large number of staged/unstaged deletions (old `Clasificadores/` units and `__history` files, `BD/`); treat `git status` noise in those paths as pre-existing, and don't restore or commit it unasked.
- **Asignación de responsables (SQL Server):** `UAsignacionDatos.pas` (reglas + escritura transaccional, sin VCL) y `UAsignacionNodos.pas` (pantalla por código, sin .dfm; se abre desde Administración de usuarios, botón creado en `UUserGest.FormShow` solo con `TBD = 'S'`). `tb_nodo_egd` admite varios EGD por nodo (clave `IdEstructura,id,user_id`); el EGD ve los descendientes y actúa solo en su nodo.
- **Procesos archivísticos (rediseño de Préstamos, Transferencias y Depuración; fase F0 hecha, 2026-11-12):** diseño en `docs/superpowers/specs/2026-11-12-prestamos-transferencias-depuracion-design.md`, plan maestro `...-prestamos-transferencias-depuracion.md`, plan de F0 `...-procesos-f0-base-comun.md`, maquetas aprobadas en `docs/superpowers/maquetas/2026-11-12-procesos-maqueta.html`. Se DESESTIMAN `UPrestamos`, `UTransferencias`, `UProgresoTransferencia` y `UDepuracion` (siguen funcionando hasta que cada fase los reemplace). Base común sin VCL con pruebas: `UProceso` (pasos, condiciones de avance, cancelación, quién inicia, `EstadoDelPaso`), `UNumeracion` (`2026-0047`, `T-2026-02`, `D-2026-01`), `UCandados` (clave de documento tolerante a mayúsculas/espacios), `UAutorizacion` (acta y acuerdo de la Comisión), `UEsquemaProcesos` + `SCRIPTS/procesos_tablas.sql` (tablas `prc_proceso`, `prc_unidad`, `prc_evento`, `prc_autorizacion`, `prc_bloqueo`; se crean en `UpDateDB`), `UProcesosDatos` (crear, avanzar con control de concurrencia, cancelar, candado por documento con `prc_bloqueo` cuya clave primaria es el documento, bloqueos por nodo en una consulta) y `UProcesosInterruptor` (`procesos_clasico.flag`, `procesos_error.log`). `UProcesoBase` (VCL, hereda de `TFormClasificadorBase`) agrega indicadores, pestañas de estado y tira de pasos; se abre embebida con `TMAIN.AbrirProceso` (ruta «Procesos» del shell). `UProcesoDemo` y el desvío `ARCHIGENIO_PROCESOS_DEMO=1` en `TMAIN.ShellSeccion` (sección Préstamos) son TEMPORALES y se eliminan en la primera tarea de F1. Las pruebas de `UProcesosDatos` y de `UEsquemaProcesos` contra SQL Server se omiten sin `ARCHIGENIO_TEST_DB`: ejecutarlas antes de F1. La suite tiene 23 errores previos ajenos (`UPruebasSeriesDatos`/`UPruebasVariablesDatos`, `cl_series` inexistente en la base de pruebas por defecto).
